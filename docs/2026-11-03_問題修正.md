# Hooong 問題修正與驗證（2026-11-03）

本次處理前一輪測試發現的權限、簽核、庫存、實驗歸屬、配方狀態、版本快照及實驗草稿問題。「忘記密碼」依使用者指示跳過。

## 修正內容

| 項目 | 修正後行為 |
|---|---|
| 權限矩陣 | 主要業務 API 依模組的 view/create/edit/delete 權限判斷；一般實驗室人員無法新增供應商或風險，經理可依既有設定新增、修改供應商。畫面按鈕同步依權限呈現，權限快取依登入 token 隔離。配方核准／退回仍限主管及管理員。 |
| 簽核 | 驗證表單類型、實際表單、關卡名稱、順序與角色；禁止覆寫既有簽名。原有跳關限制及後關已簽時不可撤回前關的規則保留。管理員可處理各關卡。 |
| 庫存 | 拒絕負數、字串、null、未知異動類型及超量出庫。ADJUST 可明確設為零；異動與紀錄在同一交易完成，並用比較更新避免同時異動時覆蓋庫存。 |
| 實驗歸屬 | 更新或刪除組別、步驟、樣品、附件前，核對它們屬於網址中的實驗；批次步驟更新也核對全部步驟。 |
| 配方狀態 | 65 筆既有資料轉為系統代碼：草稿→DRAFT、審核中→REVIEWING、已發布→PUBLISHED、已凍結→INACTIVE（停用）。新配方由 DRAFT 開始，一般更新接口不得直接變更審核狀態。 |
| 版本紀錄 | 65 筆配方補建當前組成快照，保留原本 currentVersion。紀錄明確標示修補時間與用途；未重建未知的早期版本。示範資料產生器改為有效狀態及真正的初始版本。 |
| 助理草稿 | 先整理基本草稿，明確顯示來源及待補資訊；可辨識範本、日期、溫度組別與重複次數。另行選擇本機 AI 後，僅補充簡短觀察與紀錄建議，30 秒期限、不自動重試。模型不能重寫草稿條件；步驟中的新數字或操作設定會被濾除。補全失敗時保留基本草稿，確認及儲存仍需人工核對。 |

## 驗證

- 後端共 12 個測試檔、114 項測試通過（原有 100 項，加 14 項回歸測試）。
- 34 項實際接口／資料庫驗證全部通過，包括角色限制、主管簽核、禁止覆寫簽核、非法庫存、超量出庫、同時入庫、跨實驗更新拒絕、草稿人工確認後建立四個組別。
- 最後一輪實際本機模型呼叫成功：基本草稿約 1.4 秒，AI 補全約 13.6 秒；原有 25／30 度、日期及人工確認要求均保留。這是本次單次測量，並非所有需求的效能保證。
- 前後端正式版建置通過。
- 修改過的 13 個前端檔案與原版本比較，未增加 lint 規則違反。專案原有的全站 lint 問題未納入這輪功能修正；既有分包大小提醒仍存在。
- 合成資料已清理。除預期新增的 65 筆當前版本快照外，各應用資料表筆數與測試前基準相符。
- 修補工具已用合成配方驗證套用、再次執行無變更，以及回復流程；正式 65 筆套用後再次預覽為 0 筆待修補。

此結果驗證本次修改的情境；並非完整多人負載、每個角色的全部操作、所有瀏覽器或列印流程驗收。管理員專用功能與 PDF／列印仍有前輪未驗證範圍。

## 配方資料修補工具

工具：`backend/scripts/repair-formula-integrity.ts`，在 backend 目錄執行，預設只預覽。

```sh
npx tsx scripts/repair-formula-integrity.ts
npx tsx scripts/repair-formula-integrity.ts --apply --backup /absolute/private-backup.json
npx tsx scripts/repair-formula-integrity.ts --rollback /absolute/private-backup.json
```

可加 `--ids 1,2` 限定配方。執行前會建立私人備份，交易內重新核對資料；配方自修補後若已變動，回復會停止，避免覆蓋後續工作。版本記錄中的管理員關聯僅供記錄修補作業，說明欄明確註記不代表原始作者或歷史重建。
