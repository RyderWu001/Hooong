## 已修正的既有 Bug

**AI 問答（知識庫）流量限制 middleware 錯誤，導致每次呼叫必定 500**
- 檔案：`backend/src/middleware/rateLimit.ts`、`backend/src/index.ts`、`backend/src/routes/knowledge.ts`
- 原因：`aiLimiter` 掛載在 `requireAuth` 之前執行，`req.user` 永遠是 undefined，導致一律走 IP 限流分支；該分支把 Express `Response` 物件誤傳給 `ipKeyGenerator` 當 IPv6 子網路遮罩參數，套件內部解析 IP 直接拋例外
- 修正：把 `aiLimiter` 移到 `requireAuth` 之後才掛載（讓「以登入者為單位計數」的設計真正生效），並修正 `ipKeyGenerator` 呼叫參數
- 這個 bug 是既有問題，跟本次功能改動無關，但完全擋住 AI 問答功能，一併修掉

## 功能決策紀錄（是否要加更多刪除功能）

跟使用者討論後的結論：
- **原物料模組**：廠商暫不需要，已下架選單與路由（後端 API 保留，之後要恢復只需加回兩行）
- **樣品管理 standalone 列表頁**：不加刪除鍵。樣品本來就能在實驗詳情頁裡刪，standalone 頁面只是少一個捷徑，非必要
- **實驗結果管理**：不加刪除鍵。結果紀錄是 QC 稽核資料的核心（評分、結論、異常紀錄），做錯應該用「編輯」修正而非刪除重來；真的建錯的極端情況可以用「刪除實驗」連帶清掉，不需要額外開放刪除結果的入口
- **實驗管理**：新增的「刪除實驗」限定 ADMIN 角色，作為修正誤建資料的工具，不做成一般操作流程的一部分
